# Bookmark Manager V1 运维手册（BM-V1-808）

适用版本：V1。本文保存通用迁移、备份、恢复和回滚规则，正文命令以 Docker Compose 为基线。
每节标注：`[破坏性]` 表示会修改/删除数据或服务；平台入口中的命令与正文不同时，以平台入口为准。

平台快速入口：

- [fnOS Docker 独立部署指南](fnOS部署指南.md)
- [1 GB VPS 独立部署指南](1GB-VPS部署指南.md)

两套平台部署互相独立，不共享数据库、管理员、Session 密钥或备份保留链；fnOS 使用 Docker Compose，1 GB VPS 使用单文件 `qianqi` + systemd。

## 1. 环境与目录布局

| 路径 | 内容 | 权限 |
| --- | --- | --- |
| `/opt/bookmark/source` | 应用代码（只读，构建上下文） | root |
| `/opt/bookmark/deploy` | compose / Caddyfile / .env | root |
| `/opt/bookmark/backups` | 备份（bind 挂载） | uid 10001 |
| `/data`（Docker 卷 app-data） | 数据库 `bookmarks.db`、`import_tmp` | 容器内 app(10001) |

端口：宿主机仅 80/443（Caddy）；应用 8000 只在 docker 内部网络，公网不可达。

## 2. 全新安装（演练路径 1：全新部署）

1. 安装 Docker Engine + Compose v2（发行版文档）。
2. `mkdir -p /opt/bookmark/deploy /opt/bookmark/backups && chown -R 10001:10001 /opt/bookmark/backups`
3. 拷贝代码与编排文件到 `/opt/bookmark/{source,deploy}`。
4. `cd /opt/bookmark/deploy && cp .env.production.example .env`
   - 生成密钥：`openssl rand -hex 32` 分别填入 `SESSION_SECRET` 与 `CSRF_SECRET`；填写 `DOMAIN`。
5. 启动并执行初始迁移：
   ```
   docker compose up -d --build
   docker compose exec app python -m alembic upgrade head
   docker compose restart app        # 迁移后重启以通过 ready 检查
   docker compose ps                 # app 应为 healthy
   ```
6. 创建管理员：首次访问站点会引导创建（若未引导，用 `scripts.admin` 见 §7）。
7. 验收：`curl -fsS https://<DOMAIN>/health/ready` 返回 `{"status":"ok"}`。

## 3. 升级发布（演练路径 2：上一版本升级）

流程固定为：备份 → 迁移 → 新镜像 → ready 检查；任何一步失败即停止（§9 回滚）。

```
# 0) 固定当前发布镜像标签（不用浮动标签）
docker compose config | grep image:

# 1) 备份（失败则停止）
docker compose exec -T app python -m scripts.backup --type weekly --dir /data/backups

# 2) 拉取/构建候选镜像并打发布标签（如 1.1.0）
docker compose build app
docker tag bookmark-manager-v1:1.0.0 bookmark-manager-v1:1.1.0-rc1

# 3) 维护窗口内先跑迁移（迁移失败 -> 回滚，见 §9，不启动新镜像）
docker compose stop app
docker compose run --rm app python -m alembic upgrade head
#    若失败：docker compose start app（旧代码+旧库不变），发布中止。

# 4) 启动候选并做 ready 检查
sed -i 's/IMAGE_TAG=.*/IMAGE_TAG=1.1.0-rc1/' deploy/.env
docker compose up -d app
docker compose ps                      # healthy 后才可放流量
curl -fsS https://<DOMAIN>/health/ready
```

**应用版本与数据库 revision 不匹配演练**：启动前人为回退 `alembic_version` 或升级代码但不迁移 → `/health/ready` 应 503（`reason=revision_mismatch` 仅进日志），Caddy 仍返回站点但页面会看到一致性校验失败的错误响应，据此中止发布。

## 4. 备份（每日自动 + 手动）

自动调度（示例 `/etc/cron.d/bookmark-backup` 见 `deploy/cron-backup.example`）：
- 每日 daily（保留 7 份）、周日 weekly（保留 4 份）、每月 1 日 monthly（保留 12 份）；
- 备份 = SQLite Backup API 在线快照 → `integrity_check` → SHA-256 清单 → 原子改名；
- 失败不覆盖最近成功备份（先写 `.tmp`）。

手动：`docker compose exec app python -m scripts.backup --type daily --dir /data/backups`

异机副本（可选，建议启用）：把 rclone/对象存储挂载到宿主机后：
```
OFF_SITE_BACKUP_DIR=/mnt/offsite \
BACKUP_ENCRYPT_PASSPHRASE=$(cat /etc/bookmark/backup-key) \
docker compose exec -T app python -m scripts.backup --type daily --dir /data/backups --skip-retention
```
- 有口令时副本以 AES-256-CBC（openssl -pbkdf2）加密，本地明文备份始终保留；
- 上传失败时日志可见（`OFFSITE_FAILED`）且本地备份不受影响；
- 每周核对 `ls -lt /opt/bookmark/backups` 与异机目录。

恢复演练（建议每月）：见 §5，输出保留在 `/var/log/bookmark-restore.log`。

## 5. 恢复（灾难恢复与演练）

```
# 在独立临时目录核对备份（不触碰生产库）：
docker compose exec app python -m scripts.restore_verify --backup /data/backups/<file>.db

# 实际恢复（生产替换，[破坏性]：先停写）
docker compose stop app
cp /opt/bookmark/backups/<file>.db /data/bookmarks.db            # 或 docker cp 进卷
docker compose run --rm app python -m alembic upgrade head       # 迁移到目标版本
docker compose start app
curl -fsS https://<DOMAIN>/health/ready && curl -fsS https://<DOMAIN>/bookmarks
```
恢复后抽查：管理员登录、分类树、标签关联、回收站计数（恢复工具已输出抽样关系）。

## 6. 日志查看与磁盘告警

- 日志：`docker compose logs -f app`；已按 json-file 轮转（10 MB × 5 份，占用上限约 50 MB/服务）；
- 磁盘告警建议：备份目录 >90%、根分区 >85% 时触发告警（cron + df）。

## 7. 管理员解锁与改密（忘记密码/账户锁定）

```
docker compose exec app python -m scripts.admin list
docker compose exec app python -m scripts.admin unlock admin
docker compose exec app python -m scripts.admin reset-password admin '<新密码>'
```
说明：解锁清零失败计数；重置密码同时使该账户所有会话失效（session_version+1），无破坏性。

## 8. 密钥轮换（SESSION_SECRET / CSRF_SECRET）

[破坏性：轮换后所有会话与 CSRF cookie 失效，全员重新登录；导入预览任务（PREVIEWED）将 403（nonce 变化）]
1. 备份库（§4）；
2. 编辑 `deploy/.env` 生成两个新密钥；
3. `docker compose up -d app`；
4. ready 检查 + 重新登录验证；旧导入任务重新上传。

## 9. 回滚（上一版本）

前提：发布固定标签（如 1.0.0）且发布前有备份。
```
docker compose stop app
# 库无需回滚（迁移失败时尚未改动；成功回滚=应用降级到旧镜像，库保持新版本时执行旧代码会 revision 不匹配 -> 请先恢复发布前备份并校验）
# 场景 A：迁移失败/未迁移
IMAGE_TAG=1.0.0 docker compose up -d app        # 旧镜像 + 原库
# 场景 B：迁移已成功但应用异常
cp /opt/bookmark/backups/<发布前备份>.db /data/bookmarks.db   # [破坏性] 回滚库到发布前
docker compose run --rm app python -m alembic upgrade head
IMAGE_TAG=1.0.0 docker compose up -d app
docker compose ps && curl -fsS https://<DOMAIN>/health/ready
```

## 10. 已知限制与安全检查清单

- 基础镜像采用固定补丁版本标签；生产建议按 Dockerfile 注释 pin 平台 digest；镜像漏洞扫描（如 trivy）与三浏览器人工回归在发布验收环境执行（阶段 10）；
- 异机加密依赖宿主机 openssl；离线加密副本的还原命令：
  `openssl enc -d -aes-256-cbc -pbkdf2 -in <file>.db.enc -out restored.db -pass env:BACKUP_ENCRYPT_PASSPHRASE`
- 每步执行前后记录：时间、备份文件、迁移 revision（`alembic_version`）、ready 状态。
